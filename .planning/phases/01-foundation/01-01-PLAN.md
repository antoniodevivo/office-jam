    IMPORTANT: This is a greenfield project. The workspace must be created from scratch. The existing repo has only .planning/, .claude/, .gitignore, and CLAUDE.md.

    STRATEGY: Because this repo already has a git history and planning files, we CANNOT use `create-nx-workspace` (which creates a new directory and initializes git). Instead, manually initialize the Nx workspace by installing packages and using generators.

    Step 1: Initialize Nx in the existing repo.
    - Run `npm init -y` to create package.json (if not present)
    - Install Nx and core plugins:
      ```
      npm install -D nx@22 @nx/workspace@22 @nx/node@22 @nx/react@22 @nx/vite@22 @nx/js@22 @nx/esbuild@22 typescript@~5.8.0 @types/node
      ```
    - Run `npx nx init` if needed, or manually create `nx.json` with:
      ```json
      {
        "$schema": "./node_modules/nx/schemas/nx-schema.json",
        "namedInputs": {
          "default": ["{projectRoot}/**/*", "sharedGlobals"],
          "production": ["default", "!{projectRoot}/**/?(*.)+(spec|test).[jt]s?(x)"],
          "sharedGlobals": []
        },
        "targetDefaults": {
          "build": {
            "dependsOn": ["^build"],
            "inputs": ["production", "^production"],
            "cache": true
          },
          "test": {
            "inputs": ["default", "^production"],
            "cache": true
          }
        }
      }
      ```

    Step 2: Create tsconfig.base.json at root:
    ```json
    {
      "compileOnSave": false,
      "compilerOptions": {
        "rootDir": ".",
        "sourceMap": true,
        "declaration": false,
        "moduleResolution": "node",
        "emitDecoratorMetadata": true,
        "experimentalDecorators": true,
        "importHelpers": true,
        "target": "es2015",
        "module": "esnext",
        "lib": ["es2017", "dom"],
        "skipLibCheck": true,
        "skipDefaultLibCheck": true,
        "baseUrl": ".",
        "paths": {
          "@office-jam/shared": ["libs/shared/src/index.ts"],
          "@office-jam/db": ["libs/db/src/index.ts"]
        }
      },
      "exclude": ["node_modules", "tmp"]
    }
    ```

    Step 3: Generate applications using Nx generators:
    ```
    npx nx g @nx/node:application apps/api --framework=fastify --e2eTestRunner=none
    npx nx g @nx/react:application apps/web --bundler=vite --e2eTestRunner=none --style=css
    ```

    Step 4: Generate shared libraries:
    ```
    npx nx g @nx/js:library libs/shared --bundler=none --unitTestRunner=vitest
    npx nx g @nx/js:library libs/db --bundler=none --unitTestRunner=vitest
    ```

    Step 5: Verify path aliases in tsconfig.base.json. After generators run, confirm the paths block contains:
    - `"@office-jam/shared": ["libs/shared/src/index.ts"]`
    - `"@office-jam/db": ["libs/db/src/index.ts"]`
    If generators created different aliases (e.g., `@office-jam/shared` might already be set correctly, or might need adjustment), update to match the locked decision.

    Step 6: Update .gitignore to include:
    - node_modules/
    - dist/
    - tmp/
    - .nx/
    - libs/db/generated/
    - *.env
    - !.env.example
    (Preserve any existing entries from the current .gitignore)

    Step 7: Verify the Fastify app entry point (`apps/api/src/main.ts`) contains a working Fastify server. The Nx generator should produce this automatically. Ensure it listens on `process.env.PORT || 3000` and host `0.0.0.0` (needed for Docker later).

    Step 8: Verify the React app entry point (`apps/web/src/main.tsx`) renders a root component. The generator should produce this automatically.

    Step 9: Set `libs/shared/src/index.ts` to export a placeholder comment:
    ```typescript

    ```

    Step 10: Set `libs/db/src/index.ts` to export a placeholder:
    ```typescript

    // Prisma client will be configured in Plan 02
    export {};
    ```

    Step 11: Run `npx nx run-many --target=build` to verify all packages compile successfully.

    NOTES:
    - Pin TypeScript to ~5.8.x (NOT 6.0.x) per research -- Nx 22 compatibility.
    - If generators prompt for choices, prefer: esbuild for api bundler, vite for web bundler, vitest for test runner.
    - The Nx generators will create project.json, tsconfig.json, tsconfig.app.json files automatically -- do not hand-create these.
